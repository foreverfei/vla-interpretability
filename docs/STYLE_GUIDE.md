# 项目文档表述规范

本规范用于统一仓库中的项目管理和实验记录语言。

## 1. 固定术语

| 统一用语 | 说明 |
|---|---|
| A 组：表征追踪 | 首次出现时可标注 Representation Tracing |
| B 组：视觉干预与行为分析 | 首次出现时可标注 Visual Intervention and Behavior Analysis |
| 配对实验 | 同一模型、任务、初始状态和随机种子下，仅实验条件不同 |
| 策略查询 | policy query，模型重新生成一次动作块 |
| 环境步 | environment step，仿真环境执行一步 |
| 动作块 | action chunk，一次策略查询输出的一组连续动作 |
| 实验产物 | 配置、日志、表格、图和失败样本等 |
| 阶段验收 | 使用“通过 / 补充后复验 / 不通过 / 暂停” |
| 结论范围 | 说明结果支持和不支持的内容 |

## 2. 统一文档结构

任务和周计划统一使用：

```text
目标
任务
分工
交付物
验收标准
本阶段范围
```

实验报告统一使用：

```text
实验信息
研究问题
实验设置
数据完整性
结果
失败样本
结论
结论范围
下一步
```

## 3. 表述要求

- 先写具体任务和可检查结果，不写口号化描述。
- 中文为主，必要时在首次出现时保留英文术语。
- 不使用“证明模型理解了”“揭示内部机制”等超出证据范围的表述。
- 不把流程完整、指标可视化或单个案例写成论文贡献。
- 对失败、缺失和未复现结果如实记录。
- 同一概念在所有文档中使用同一名称。
